# 🧱 1️⃣ Architecture globale

## 🪟 MainFrame

Responsabilité unique :

* créer la JFrame
* gérer le `CardLayout`
* gérer la navigation (back / next)
* ne contient PAS de logique métier

```text
MainFrame
 ├── TopPanel (fixe)
 └── CardLayout
      ├── MenuPanel
      └── WorldGenPanel
```

✔ Très bon choix.

# 🧭 2️⃣ Navigation

Le `TopPanel` reste constant → parfait.

Tu as deux options propres :

### Option A (simple)

Le `MainFrame` contient :

* `CardLayout`
* méthode `showPage(String id)`

Les boutons `back/next` appellent `mainFrame.showPage("GEOLOGY")`.

---

### Option B (plus propre long terme)

Créer un petit `NavigationController`.

Ça évite que tous les panels connaissent la frame.

## 🧩 Structure idéale du ParameterPanel

```text
ParameterPanel (BorderLayout)
 ├── NORTH : StepSelectionPanel
 │         ├── JCheckBox / JComboBox
 │         ├── Undo / Redo
 │
 ├── CENTER : SliderContainer (GridBagLayout)
 │
 └── SOUTH : GenerateButton
```

Ça te permet de :

* changer les sliders dynamiquement
* garder la structure fixe

# 🔁 6️⃣ Undo / Redo

Très bonne idée.

Architecture propre :

```
WorldState
HistoryManager
 ├── undo()
 ├── redo()
 └── pushState()
```

Quand on clique sur Generate :

1. clone du world
2. push dans history
3. génération
4. update map

⚠ Important : ne fais PAS undo sur les sliders
Fais undo sur l’état du monde.

# 🧩 8️⃣ Checkbox vs ComboBox ?

Honnêtement :

Si tu choisis une seule step à la fois →
👉 `JComboBox` est plus propre qu’une checkbox.

Checkbox = activation/désactivation
ComboBox = sélection unique

Donc :

```
JComboBox<GenerationStep>
```

sera plus cohérent.

# 🧠 Petite amélioration future

Si tu veux passer niveau supérieur :

Créer une interface :

```java
interface GenerationStep {
    String getName();
    List<Parameter<?>> getParameters();
    void apply(World world, GenerationContext context);
}
```

Et ton WorldGen devient :

```java
for (GenerationStep step : pipeline) {
    step.apply(world, context);
}
